## 一、项目概述

### 1.1 一句话定位

**灵感表**是一个「先捕捉、后深化、再推进」的三级灵感管理 Web 应用：一级界面像微软 To Do 一样以极低的成本随手记录碎片灵感；二级界面用结构化构思框架把灵感展开成具体内容；三级项目管线（五态分类）让确认要做的灵感一路推进到完结——从一句话点子到项目落地全程管理。

### 1.2 背景与痛点

- 灵感总在碎片时间出现（通勤、阅读中、睡前），现有笔记工具打开成本高、结构重，来不及记就忘了
- 待办工具足够轻，但只装得下"一句话"，灵感后续的展开与推敲无处安放
- 确认要做的灵感进入执行期后，计划书、任务清单、进度状态散落在各处，没有一个地方能"从想法管到落地"
- **灵感表 = 待办工具的「轻」 + 笔记工具的「深」 + 项目工具的「跟踪」**

### 1.3 用户故事（核心场景）

1. 我在地铁上想到一个点子，打开网页，**≤ 2 次交互**完成一条记录，继续干别的
2. 新灵感进入暂存区，我用内置的联网检索入口查一查有没有类似项目，把参考链接和查重结论记下来
3. 周末有空时，我翻看本周记录，挑一条进入详情页，用构思框架（核心想法 / 为什么 / 怎么做 / 风险疑问）把它展开成方案
4. 确认要做的灵感标记为「待推进」，写好任务书；开工后推进到「进行中」，**导入项目计划书 MD 文件**，应用自动列出子任务，我逐项勾选，进度一目了然
5. 完成的项目归入「已完结」；放弃的移入「已废弃」留档，而不是删除

### 1.4 项目范围

- **本期（v1.0）**：纯前端单页应用，本地存储，零账号、零依赖、双击即用
- **暂不做**（列入后续展望）：云同步、多人协作、移动原生 App

## 二、需求分析

### 2.1 功能需求

**模块 A：灵感速记（一级界面，仿 MS To Do）**

| 编号 | 功能 | 说明 |
|---|---|---|
| A1 | 快速添加 | 列表顶部常驻输入框，回车即存、可连续录入；可指定添加到某分组 |
| A2 | 灵感列表 | 复选框（点击 = 完结归档）、标题、星标（重要）、状态徽标 |
| A3 | 分组管理 | 左侧边栏自定义分组（增删改名、主题色）；灵感可跨组移动 |
| A4 | 智能视图 | 「全部 / 重要（星标）」+ 五态视图（新灵感 / 待推进 / 进行中 / 已完结 / 已废弃），均带角标计数 |
| A5 | 编辑与删除 | 行内重命名、删除（带撤销提示，防误删） |
| A6 | 排序与搜索 | 按创建时间 / 更新时间 / 手动排序；关键词搜索标题与内容 |

**模块 B：灵感深化（二级界面，详情面板）**

| 编号 | 功能 | 说明 |
|---|---|---|
| B1 | 详情面板 | 点击灵感条目，**右侧滑出详情面板**（同 MS To Do 交互），不离开列表；面板内提供删除入口（二次确认防误删） |
| B2 | 内容编辑 | 标题、自由备注（多行文本），自动保存 |
| B3 | 构思框架 | 内置引导式模板：① 核心想法一句话 ② 为什么值得做 ③ 怎么做（步骤清单，可勾选）④ 风险与疑问 |
| B4 | 五态流转 | 详情面板内一键切换：新灵感 → 待推进 → 进行中 → 已完结 / 已废弃，颜色徽标区分 |
| B5 | 标签与链接 | 自定义标签（含输入建议）；可粘贴参考链接 |
| B6 | 元信息 | 创建时间 / 更新时间 / 所属分组 / 状态变更时间的展示与修改 |

**模块 C：项目管线（三级，v1.1 新增）**

| 编号 | 功能 | 说明 |
|---|---|---|
| C1 | 五态管线 | 全部灵感分为五类：**新灵感（暂存待查重）/ 待推进 / 进行中 / 已完结 / 已废弃**；侧栏五态视图 + 角标；列表内可快捷流转、批量流转 |
| C2 | 联网调研助手 | 「新灵感」详情面板内置快捷检索入口（必应 / 百度 / GitHub / 知乎），一键用标题发起查询（新标签打开）；可记录参考项目链接与查重结论（重复 / 近似 / 空白） |
| C3 | 任务书 | 「待推进」详情面板内置任务书区块：目标、范围、里程碑、验收标准；支持从构思框架一键生成初稿 |
| C4 | MD 计划导入 | 「进行中」灵感可导入 `.md` 项目计划书：本地解析（不上传）标题层级与任务清单（`- [ ]` / `- [x]`），生成可折叠、可勾选的任务树 |
| C5 | 进度跟踪 | 任务勾选自动汇总进度百分比，回写列表条目与详情面板；重新导入同一文档时**合并保留已勾选状态** |

### 2.2 非功能需求

- **本地优先**：数据存 localStorage，无网络可用；MD 文件在浏览器本地解析，不上传；提供 JSON 导入 / 导出备份
- **响应迅速**：添加、勾选等核心操作反馈 < 100ms
- **响应式**：桌面为主（侧栏 + 列表 + 详情三栏），窄屏折叠为单栏
- **明暗双主题**：跟随系统 + 手动切换
- **视觉还原**：布局、配色、交互（圆圈勾选动画、右滑详情）对标微软 To Do

## 三、技术方案

### 3.1 技术选型

| 层 | 选择 | 理由 |
|---|---|---|
| 结构 | 单页应用（SPA），列表视图 + 详情面板叠加态 | 匹配 MS To Do 的交互模型 |
| 技术 | 原生 HTML + CSS + JavaScript（ES6+），零框架零构建 | 双击即开、无环境依赖；后期可无痛迁移框架 |
| 样式 | CSS 变量主题系统（每个分组一个主题色） | 「换组换色」是 MS To Do 的视觉灵魂 |
| MD 解析 | 原生 JS 正则解析（FileReader，不依赖外部库） | 支持 CommonMark 标题层级与任务列表基本语法，容错处理 |
| 存储 | localStorage（JSON 序列化）+ 导出 / 导入 | 本期零后端 |
| 备选 | Vue 3（CDN 版，免构建） | 若状态管理复杂度超预期，可在阶段二前切换，数据模型不变 |

### 3.2 数据模型（v1.1）

```js
Group = { id, name, color, sortIndex }

Idea  = {
  id, groupId,
  title, note,                                   // 速记标题 + 自由备注
  status: 'new'|'todo'|'doing'|'done'|'dropped', // 五态管线
  starred: false,
  steps: [{ text, done }],                       // 构思框架 · 步骤清单
  why: '', risks: '',                            // 构思框架 · 价值与风险
  research: {                                    // 新灵感 · 调研（C2）
    refs: [{ title, url }],                      // 参考项目链接
    verdict: 'dup'|'similar'|'blank'|''          // 查重结论
  },
  brief: { goal, scope, milestones, acceptance },// 待推进 · 任务书（C3）
  plan: {                                        // 进行中 · 计划导入（C4/C5）
    fileName, importedAt,
    tasks: [{ heading, text, done, lineNo }]
  },
  tags: [], links: [],
  createdAt, updatedAt, statusChangedAt
}

Store = { version, groups[], ideas[], settings: { theme, sortBy } }
```

状态流转规则：`new → todo → doing → done`，任意状态可转 `dropped`；`done / dropped` 可恢复。

### 3.3 界面结构（仿 MS To Do）

```
┌──────────┬──────────────────────┬──────────────┐
│ 搜索      │  列表标题（分组主题色）   │              │
│ 智能列表   │  ┌─ 快速添加输入框 ─┐   │              │
│  全部     │  │ ○ 灵感条目       │   │   详情面板    │
│  重要     │  │ ○ 灵感条目 ★     │   │  （点击滑出）  │
│  ● 新灵感  │  │ ○ ...           │   │  标题/备注    │
│  ● 待推进  │  └─────────────────┘   │  构思框架     │
│  ● 进行中  │                       │  调研/任务书   │
│  ○ 已完结  │                       │  MD任务树     │
│  ○ 已废弃  │                       │  状态流转     │
│ 自定义分组 │                       │              │
└──────────┴──────────────────────┴──────────────┘
（● = 活跃态视图，带角标计数）
```

## 六、风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| MD 格式多样（标题层级、任务语法变体） | 解析不准、进度失真 | 解析器支持 CommonMark 基本语法并容错；导入后允许手动修正任务；阶段四用真实计划书实测 |
| localStorage 容量受限 / 被清理 | 数据丢失 | 阶段五提供导入导出；版本迭代可升级云端存储 |
| UI 还原度争议 | 返工 | 阶段一即产出静态稿对照验收，尽早锁定视觉 |
| 功能范围蔓延 | 工期失控 | 严格按分期推进，新增想法记入「后续展望」 |
| 原生 JS 状态管理复杂 | 代码难维护 | 预留 Vue CDN 迁移路径，数据模型保持不变 |
